# Project Instructions

You are building this as a production-quality portfolio project.

## Default behavior

Do not ask clarifying questions unless the task is blocked.
Make reasonable assumptions and document them in the README.
Prefer completing a working version over stopping for small decisions.
When choices exist, choose the simplest production-minded option.
Batch any needed questions into one short list before coding.
Do not ask one question at a time.
Do not stop after planning unless explicitly told to stop.
After planning, implement the plan.

## Build expectations

Use Next.js App Router, React, TypeScript, and Tailwind CSS unless the prompt says otherwise.
Use clean folder structure.
Use reusable components.
Use mock data first so the app runs without paid APIs.
Do not commit secrets.
Use .env.example for placeholder variables.
Add README, .gitignore, GitHub Actions, issue templates, and PR template.
Run lint and build before final response.

## UI expectations

The interface should be dynamic, unique, polished, and portfolio-ready.
Avoid generic template layouts.
Use mobile-first responsive design.
Use accessible colors, keyboard navigation, visible focus states, and reduced-motion support.
Use animation only when it improves the experience.

## Git expectations

Set up Git after the first successful scaffold build.
Commit major milestones separately.
Use clear commit messages.
Never commit .env files, API keys, node_modules, .next, or local build artifacts.

## Final response format

Summarize:
What was built
How to run it
Important files
Known tradeoffs
Next improvements
